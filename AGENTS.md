# Agent guidelines

## What this repo is

This repository contains the TypeScript implementation of Linked Markdown. The
code is Node-compatible and the toolchain is Bun (cutover tracked in
wazootech/workspace#50); the package is published to JSR, so it also runs for
Deno consumers.

## How to work here

- `jsr.json` is the source of truth for the published package (name, version,
  exports, publish list, import map). `package.json` and `bun.lock` are what Bun
  installs; `bun run check:manifests` (`scripts/check-manifests.ts`) fails when
  the two drift. JSR dependencies are `npm:@jsr/<scope>__<name>` aliases in
  `package.json`, resolved through the `@jsr` scope in `bunfig.toml`.
- Use `node:` APIs, never `Deno.*` (`node:fs`, `node:path`, `node:process`).
- Tests use `node:test` and `node:assert/strict`, run by `bun test`; no
  `bun:test` and no `@std/assert`.
- Run `bun run ci` for the whole local gate: `bun fmt --check`, Oxlint, `bun
check`, the manifest check, and the tests.
- Keep exported API changes reflected in README examples.
- Publishing goes through the `jsr` CLI (`bun run publish:dry`, `bunx jsr
publish`), which bundles its own Deno-based publisher: no Deno install is
  needed. Its slow-type check is stricter than Deno 2.9's, so exported constants
  need explicit types. `deno.lock` is regenerated by `jsr publish` and ignored.

## Code health

Family-wide rules live in the
[wazootech workspace constitution](https://github.com/wazootech/workspace/blob/main/AGENTS.md#code-health-standards);
this repo's specifics:

- Before pushing, run `bun run ci`; CI runs it on every pull request and push to
  `main`.
- Oxlint (`.oxlintrc.json`, `--deny-warnings`) enforces `no-explicit-any` and
  `ban-ts-comment` (no `@ts-ignore`), and `tsconfig.json` sets `strict: true`.
  `bun fmt` is the formatter; `.prettierignore` lists what it skips.
- `secret-scan.yml` runs gitleaks on every pull request and push to `main`;
  never commit credentials.
- Workflow actions are pinned to full commit SHAs with a version comment. Bun
  floats on `1.x` in every workflow (the one allowed unpinned toolchain, owner
  decision 2026-11-23, wazootech/workspace#50) and CI installs with
  `bun install --frozen-lockfile`, so commit any `bun.lock` change.
- `release.yml` publishes on a `v*` tag (or manual dispatch): it runs
  `bun run ci` and a publish dry run before `bunx jsr publish`.
- `code-health.yml` only warns: files over 120 lines of code (300 for tests) and
  `TODO`/`FIXME` without an issue link. There are no exclusions.
- `.github/CODEOWNERS` routes review to the repo owner.
